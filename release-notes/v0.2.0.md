# Profile Signal v0.2.0

Profile SignalのPresetを拡張し、プロフィール用途に合わせて表示構成を選びやすくしたReleaseです。

## 主な変更

### YAML Preset Registry

Preset定義をruntimeコード内の固定辞書から `.profile-signal/presets/*.yml` へ分離しました。

これにより、新しい公式Presetを追加するときにOrchestratorへPreset名ごとの分岐を増やさず、YAML追加中心で拡張できます。

Registryは起動時にPreset定義を検証します。

- schema version
- Preset IDとファイル名の一致
- Widget名
- Widget重複
- Theme
- 既存互換Presetの存在

### 新しいPreset

既存の `minimal / standard / full / terminal` はそのまま維持し、以下を追加します。

- `compact` — TODAY + CURRENT FOCUS
- `developer` — 現在の開発状況・Active Repository・Activity Stream中心
- `activity` — TODAY / DEV PULSE / ACTIVITY STREAM / DEV RECAP中心
- `oss` — 公開Repositoryでの開発状況・履歴中心

既存4PresetのWidget構成は変更していません。

### Release ZIP

Preset Registryと全公式Preset YAMLをRelease ZIPへ同梱します。

利用方法は従来と同じです。

1. `profile-signal-v0.2.0.zip` を取得
2. GitHub Profile Repository rootへ展開
3. `.github/profile-signal.yml` のusername / presetを設定
4. commit / push
5. `Actions → Profile Signal → Run workflow`

## 設定例

```yaml
version: 1

profile:
  username: YOUR_GITHUB_USERNAME
  timezone: Asia/Tokyo

privacy:
  public_only: true

preset: developer
theme: signal

widgets: {}
```

Preset選択後も `widgets` で個別ON/OFFできます。

## 互換性

- config schema versionは `1` のままです。
- `minimal / standard / full / terminal` の意味は変更していません。
- `privacy.public_only: true` のcontractも変更ありません。
- v0.1.0から更新する場合、既存 `.github/profile-signal.yml` は原則そのまま利用できます。
